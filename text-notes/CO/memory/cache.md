## 地址映射

### 直接映射

数据块地址的低地址位作为cache地址/行编号
cache行结构如下：
```
  | 有效位 | 分区号 | 数据块 |
```
那么主存中数据的地址如下：
```
  | 分区号 | 区内数据块地址 | 块内偏移 |
  |     主存数据块地址     |
```

### 全相联映射

数据块没有对应固定的cache行，数据块可能存放在任一cache行中
cache行结构如下

```
  | 有效位 | 主存数据块地址 | 数据块 |
```

### 组相联映射

结合直接映射和全相联映射，将cache行划分为**组**为单位，组与组之间按直接映射，组内按全相联映射
cache行结构如下：
```
  | 有效位 | 分区号 | 数据块 |
```
主存数据地址结构如下：
```
  | 分区号 | 区内数据块地址 | 块内偏移 |
```
 可以发现其实**和直接映射一致**

 - 直接映射中不同分区的，相同序号的数据块需要争用一个cache行
 - 组相联映射中，cache划分为一个一个组，不同分区的相同序号的数据块同样使用同一组cache，但是公用组内cache行，若每组分配了k个cache行，则称为**k路组相联**
    > 例如，二路组相联中不同分区中相同序号的数据块一起使用两个cache行，按全相联映射方式，每个数据块可能存放在这两个cache行中任一行

## 替换算法

当读cache未命中时，需要进行cache替换，替换算法即说明如何替换

- 随机替换

- FIFO First In First Out 先进先出算法

- LFU Least Frequent Used 最不常用算法

- LRU Least Recent Used 最近最少用算法

## 写入策略

当写cache时，使用的策略

### 写命中时

- **写回/回写法**，write-Back
    - 修改数据时，只写到cache中，暂时不写到主存，可能造成数据不一致的问题
    - 使用写回法时，cache行需要增设一标记位，脏位，标记的数据是脏数据

- **写穿法/通写法/直写法**
    - 被修改的数据同时写入cache和主存

### 写未命中时

- **写分配法**
    - 修改数据时需先分配cache行，然后修改cache行中的数据
    - 写回方式，修改数据时使用写回法
    - 写穿方式，修改数据时使用写穿法

- **非写分配法**
    - 指修改的数据直接写回主存，不分配cache行
