# 虚拟存储器  

## 概要（不是目录）  

- 虚拟内存的基本概念  
- 请求页式管理  
- 页框分配与回收  
- 页置换算法  
- 内存映射文件（Memory-Mapped Files）  
- 虚拟存储器性能的影响因素及改进方法  

## 概述  

- 请求分页管理 在分页存储管理的基础上增加了请求调页功能和分页置换功能；  
- 请求分段管理 在分段存储管理的基础上增加了请求调段功能和分段置换功能。  

## 请求分页存储管理方式  

### 硬件支持  

- 页表与分页管理方式的页表相比增加了四个字段：  
  - 状态位（标识是否调入了内存）；  
  - 访问字段（记录一段时间内的访问次数）；  
  - 修改位（标识是否被修改过）；  
  - 外存地址（通常是外存中的物理块号）；  

- 中断机制 提供必要的缺页中断机制，请求OS调入页  

- 地址变换 在分页系统的地址变换基础上增加了某些功能，如中断和页面置换。  

### 内存分配  

- 最小物理块 指进程运行必要的最少的物理块数：  

  - 对于单地址指令和直接寻址方式，至少需要2个物理块（指令一块，数据一块）；  
  - 对于单地址指令但是支持间接寻址，至少需要3个物理块；  
  - 对于指令长度大于等于2字节的机器，至少需要6个地址块（源指令或数据可能跨两个页）；  

- 分配策略  

  - 固定分配局部置换：进程的物理块数固定，页面置换时仅允许置换属于该进程的页面；  
  - 可变分配全局置换：进程物理块数可变，置换的页面可能是其他进程的页面；  
  - 可变分配局部置换：进程物理块数可变，允许系统增加或减少其物理块数。  

- 分配算法  

  - 平均分配：每个进程平均分配物理块；  
  - 按比例分配：按进程大小分配物理块；  
  - 考虑优先权的分配：将内存物理块分为两部分，一部分按比例分配，另一部分按优先权额外分配。有的实时系统中可能完全按照优先权分配内存。  

### 页面调入策略  

- 调页策略  
  - 预调入策略：预测将要访问的页面提前调入内存，目前成功率较低；  
  - 请求调入策略：仅在缺页时调入，仅调入一页。  

- 调入空间  
  - 如果当前对换区空间足够，可以从对换区调入缺页，为此应该在进程运行前将有关页面全部调入对换区；  
  - 如果对换区空间不够，对于不会修改的文件，直接从文件区调入，换出时也不必写入外存，对于可能修改的文件，换出时换到对换区；  
  - UNIX方式，进程有关文件放在文件区，所以未运行的文件都将从文件区调入，运行过被换出的文件放在对换区。  

## 页面置换算法  

- 最佳置换算法：理论最优，无法实现的算法，根据未来将要访问的情况决定替换的页面；  

- 先进先出算法：先进内存的先换出；  

- 最近最少用算法LRU：根据过去一段时间内使用的情况决定替换的页面，需要的硬件支持有移位寄存器和栈两种方式；  

- 最近最不常用算法LFU：根据过去一段时间内使用的频度决定替换的页面，实际只能记录一小段时间内的使用情况作为一次，使用移位寄存器实现；  

- clock算法：LRU的近似算法，每页设置访问位和指针链接为一个循环链表，按顺序检查访问位是否为0，若是则换出，若不是则置0，检查下一节点。称为最近未用算法。  

- 改进型clock算法：增加一个考虑因素，置换代价，需要同时考虑访问位和修改位，进行多轮扫描：  
  - 第一步：扫描队列，检查访问位A和修改位M都为0的页面，此次扫描不修改访问位；  
  - 第二步：第一步扫描未找到匹配的页面，则再扫描一次查找A = 0，M = 1的页面，并将扫描过的页面A置0；  
  - 第三步：若第二步仍失败，将所有页面A置0（相对于只检查修改位），然后按第一步重新扫描，若仍失败继续第二步扫描，此时一定能找到符合的页面。  

- 页面缓冲算法PBA：  

  对于已修改的需要换出的页面，系统可暂时不将其换出，而是在需要换出的页面积累到一定数量后一次性换出，这样可以显著减少IO操作次数；  

  需要设立两个链表：  

  - 空闲页面链表：是空闲的物理块链表，读入页面时使用第一个物理块，需要将{未修改页面}写出到外存时将该物理块挂在链表末尾，如果有进程以后需要这些页面的内容时，就可将其从链表后取下；  

  - 修改页面链表：由{已修改的页面}链接成的链表，操作类似。  

## "抖动"与工作集  

- 抖动：刚换出的页面很快需要再访问，需要重新调入，而被换出的页面又很快需要再被访问，造成页面被频繁换进换出的"抖动"现象。  

- 工作集：将某进程在时间t的工作集记为w(t,Δ)，Δ称为工作集的窗口大小，比如w(t,Δ=3)指t时刻时最近使用过的三个页面集合。  

- "抖动"的预防：  
  - 使用局部置换策略；  
  - 将工作集算法融入处理机调度，每当要调入新作业时检查进程在内存中的页面是否足够多，若足够则调入新进程，若不够则为其增加物理块数，不调入新进程；  
  - L=S准则，L指缺页之间的平均时间，S是平均缺页处理时间，当L与S接近时磁盘和处理机都可以达到较高的利用率。  
  - 选择暂停进程，基于某种原则暂停某些进程，将其调到外存中。  

## 请求分段存储管理方式  

### 硬件支持  

- 请求段表：除了请求分页机制中的访问字段、修改位、存在位和外存始址外新增了存取方式（如只读、只执行、允许读写等）和增补位（标识本次存取段是否发生增长）。  

- 缺段中断：与缺页中断类似；  

- 地址变换：与页式类似；  

### 分段的共享与保护  

- 共享段表：在系统中配置一张，记录所有共享段信息（段名、段长、内存始址、外存始址、状态和共享进程计数）及各个共享进程的信息（包含状态、进程名、进程号、段号和存取控制字段）  
  - 共享进程计数count：所共享的进程的数量；  
  - 存取控制字段（每一进程一个字段，多个进程多个）：标记所属进程的使用权限如只读，只执行等；  
  - 段号（每个进程一个字段）:标记所属进程的段号，共享段在不同进程中可能有不同的段号。  

- 共享段的分配与回收：  
  第一次分配时建立共享段表的表项，count初始化1，后续的共享进程仅需在进程的段表和共享段表的共享段中增加表项，修改计数即可；  
  回收时count减一，检查是否为0，根据结果修改、回收各表项或回收物理内存。  

- 分段保护  

  - 越界检查：由地址变换结构完成，变换过程中检查长度段号是否非法；  
  - 存取控制检查：以段为基本单位，由硬件实现；  
  - 环保护机构：抽象为一层层包裹的环结构，低编号的内环具有高优先权，一般是OS内核，中间是重要的应用和操作系统服务，外环是一般的应用程序，  
  程序可以访问相同环或低优先权环中的数据；可以调用高优先级环中的服务。
