# 应用层

## 客户服务器方式与对等网络  

客户服务器方式*C/S, client/server*与对等方式*P2P,peer-to-peer*  

## 动态主机配置协议DHCP  

- 使用传输层**UDP**协议  
- 报文类型如下：  
    - DHCP DISCOVER 发现报文  
    - DHCP OFFER 提供报文  
    - DHCP REQUEST 请求报文  
    - DHCP ACK 确认报文  
    - DHCP NACK 否认报文  
    - DHCP RELEASE 释放报文  
- 在从DHCP服务器获得可用IP地址前，客户机需要使用0.0.0.0来发送各DHCP报文，服务器使用255.255.255.255作为目的IP来广播回复  
- 通常不会给每一个网络配置单独的DHCP服务器，而是使用至少一个DHCP中继代理  

## 域名系统DNS  

- 基于**UDP**协议
- 域名层次 如：*.三级域名.二级域名.一级域名（顶级域名）
- 域名服务器层次  
    - 根域名服务器 记录所属的顶级域名的顶级域名服务器IP，  
    - 顶级域名服务器 管理在该顶级域名服务器注册的所有二级域名，  
    - 权限域名服务器 管理某个区的域名，查询过程中可能需要请求其他权限域名服务器
    - 本地域名服务器 起代理的作用，将查询报文转发到上述的域名服务器层次结构中，返回解析后的IP给用户机

## 文件传送FTP  

- 主动方式 由服务器主动发送**TCP**连接请求并携带使用的端口号，主动方式下使用20号端口传输数据  
- 被动方式 由客户端主动建立连接，服务端被动等待连接建立和数据传输请求，被动方式下使用的端口号由双方协商  
传输文件时临时建立一条连接用来传输文件，会话期间打开并保持一条用于控制的控制连接

## 电子邮件  

- 电子邮件系统的组成结构  
    - 客户机本地的用户代理，负责与邮件服务器交互
    - 邮件服务器存储和传输电子邮件
    - 基于万维网的电子邮件 通过网站使用邮件服务，不再需要SMTP和POP3，而是HTTP  

- 电子邮件格式与MIME
    - 分为信封和内容，内容由首部和主体构成  
    - SMTP只能传送ASCII码文本，非ASCII码传输**需要MIME进行转换**，MIME，*多用途因特网邮件扩展*  

- SMTP协议与POP3  
    - SMTP用于客户端和服务器，服务器与服务器之间的电子邮件发送，客户端读取服务器上的邮件使用POP3，post-office-protocol *邮局协议*，此外还有IMAP*因特网邮件访问协议*，用户可以在自己的计算机上操作服务器中的邮件，可以看出IMAP是一个联机协议  
    - SMTP和POP3都基于TCP连接，SMTP使用25号端口，POP3使用110号端口，IMAP使用143号端口   

## 万维网WWW协议  

### WWW 的概念与组成结构  

互联网的标准，规定资源格式大致如下
```
[protocol]://[www.domain.org]/path/to/resource
```

### HTTP协议，*超文本传输协议*

- HTTP协议主要用于网页的传输，基于传输层的TCP协议

- 表示网页的文件一般包含三种类型：HTML（超文本标记语言），CSS（层叠样式表）和Javascript（一种脚本语言）  
    - HTML是描述网页基本结构的语言
    - CSS用于渲染网页样式
    - JS一般用于运行交互逻辑


#### HTTP报文格式  

##### request

```
GET[SP]www.example.com/index.html[SP]HTTP/1.1[CRLF]
Connection:[SP]keep-alive[CRLF]
User-agent:[SP]Edge[CRLF]
Accept:[SP]text/html[CRLF]
Accept-language:[SP]zh-Cn, zh[CRLF]
[CRLF]
```

- `GET`表示请求的方法
- `www.example.com/index.html`是URI，该字段的新名称为target，表示目标的资源在服务器上的位置，可以带有额外查询字段用？隔开，比如：
`www.example.com/login.html?name=xx&page=14u7830121`后跟若干等号连接的键值对，之间由&隔开
- `HTTP/1.1`表示使用的HTTP版本
- [SP]表示插入的空格，[CRLF]表示返回符和换行符
一般的HTTP消息由开始行和头部，内容构成，上述例子没有body的内容，仅由请求行和头部选项部分构成

##### response

响应与请求格式上只有开始行不同，格式如下
```
HTTP/1.1[SP]200[SP]OK[CRLF]
// header
```
- 200表示响应的状态码，后跟描述短语，有的服务器会省略短语，新的HTTP/2.0中已经去除了短语部分
